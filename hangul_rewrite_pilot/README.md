# 한글 고쳐 읽기 사전 실험 묶음

이미지 속 한글이 익숙한 단어와 한 끗 다르게 적혀 있을 때(예: 김치찌게, 킴치), 비전-언어 모델이 보이는 대로 읽는지 익숙한 단어(김치찌개, 김치)로 고쳐 읽는지 재는 사전 실험입니다. 주제를 확정하기 전에 "한글에서도 이 현상이 충분히 큰가"를 하루 안에 확인하는 것이 목적입니다.

## 준비 (한 번만)

1. Python 3.11 이상과 NVIDIA GPU용 PyTorch(CUDA 버전)가 필요합니다. 이미 깔려 있으면 그대로 쓰면 됩니다. 새로 깔아야 하면 https://pytorch.org 의 설치 안내에서 운영체제와 CUDA를 고른 뒤 나오는 명령을 그대로 실행하세요. 윈도우에서 `pip install torch`만 하면 GPU를 못 쓰는 버전이 깔립니다.
2. 이 폴더에서 `pip install -r requirements.txt` 를 실행합니다.
3. 모델(Qwen/Qwen3-VL-8B-Instruct)은 처음 실행할 때 자동으로 내려받습니다. 용량이 십수 GB라 디스크 여유와 시간이 필요합니다.

## 실행 순서

```
python hangul_rewrite_pilot.py --preview     # 1) 이미지 예시만 만들기. preview 폴더를 열어 글자가 제대로 보이는지 확인
python hangul_rewrite_pilot.py --quick       # 2) 축소 실험. 문항 80개, 시행 1,728건
python hangul_rewrite_pilot.py               # 3) 전체 실험. 문항 370개, 시행 7,680건
```

- 소요 시간은 3090 기준으로 축소 실험 15~20분, 전체 실험 1~2시간으로 예상하지만 추정값입니다. 실행하면 50건마다 남은 시간이 표시됩니다.
- 중간에 꺼도 됩니다. 같은 명령을 다시 실행하면 끝난 시행은 건너뛰고 이어서 진행합니다.
- 시행 순서를 섞어 두었기 때문에, 중간에 멈춰도 모든 조건이 고르게 들어간 결과가 나옵니다. `--minutes 30` 처럼 시간을 정해 두고 멈출 수도 있습니다.
- GPU 메모리가 모자라면 `--load-4bit` 를 붙이세요(먼저 `pip install bitsandbytes`).

끝나면 `runs/<모델이름>/` 폴더의 **summary.md, results.jsonl, run_info.json** 세 파일을 보내 주세요.

## 실험 구성

| 요소 | 값 |
|---|---|
| 자극 | 정상 단어 120개(N), 한 자모만 바꾼 가짜 단어 159개(J), 흔한 맞춤법 오류 61개(M), 무작위 음절 30개(R) |
| 배치 | 단어만 / 문장 속 |
| 글자 높이 | 16px / 32px (이미지는 모두 1024x256, 흰 바탕 검은 글자) |
| 글꼴 | 나눔고딕(인쇄체) / 나눔손글씨 펜(손글씨풍) |
| 지시문 | 중립("읽은 글자만 답하세요") / 엄격("고치지 말고 보이는 대로") |
| 양자택일 검사 | J와 M 문항에 대해 보이는 글자와 익숙한 단어 중 하나를 고르게 함(보기 순서를 바꿔 두 번) |
| 디코딩 | 탐욕 디코딩, 반복 벌점 1.0 |

가짜 단어 J는 초성, 중성, 종성을 40개씩 바꾼 "비슷한 자모" 120개와 "다른 자모" 39개로 이루어져 있습니다. 실제로 있는 단어, 지명, 인명이 되는 경우는 사람이 읽어 보고 뺐습니다. 전체 목록은 `stimuli.json`, 만든 과정은 `build_stimuli.py`에 있습니다.

## 결과를 읽는 법

요약표에서 먼저 볼 것은 세 가지입니다.

1. **1번 표 (읽기 능력 점검)**: 정상 단어 정확도가 90% 이상인지 봅니다. 낮으면 글자 자체가 안 읽히는 조건입니다.
2. **2번 표 (고쳐 읽기 비율)**: 중립 지시문에서 J나 M의 고쳐 읽기 비율이 10% 이상인 조건이 있으면 이 주제로 진행합니다. 10%에 못 미치면 더 작은 글자(`--sizes 12,16`)로 한 번 더 확인하고, 그래도 낮으면 예비 주제로 바꿉니다.
3. **엄격 지시문 뒤에 남는 비율**: 고치지 말라고 해도 남는 고쳐 읽기가 새 완화 기법이 줄여야 할 몫입니다.

5번 표(양자택일)는 "봤는데 고쳐 쓴 것인지, 구별 자체를 못 한 것인지"를 가르는 자료입니다.

## 확인한 범위와 확인하지 못한 범위

- 이미지 생성, 채점, 요약표는 가짜 모델(`--backend mock`)로 끝까지 돌려 확인했습니다.
- 모델 호출 부분은 transformers 5.22.2와 torch 2.15.0에서, Qwen3-VL과 같은 구조의 무작위 가중치 축소 모델로 끝까지 돌려 확인했습니다. 이때 1024x256 이미지가 크기 변환 없이 들어가는 것도 확인했습니다(격자 16x64).
- **실제 Qwen3-VL-8B 가중치, GPU 실행, `--load-4bit` 는 확인하지 못했습니다.** 만든 환경에서 Hugging Face 접속이 막혀 있었기 때문입니다. 오류가 나면 메시지를 그대로 보내 주세요.
- 실제 모델에서 이미지가 줄어들거나 늘어나지 않았는지는 summary.md 첫머리의 "첫 입력 형태"에서 `image_grid_thw_values`가 `[[1, 16, 64]]`인지로 확인할 수 있습니다.

## 자주 나는 문제

| 증상 | 조치 |
|---|---|
| "GPU(CUDA)를 찾지 못해 CPU로 실행합니다" | PyTorch가 CPU 버전입니다. pytorch.org 안내대로 CUDA 버전을 다시 설치하세요. |
| `qwen3_vl`을 모른다는 오류 | `pip install -U transformers` |
| torchvision 관련 오류 | `pip install torchvision` (PyTorch와 같은 방식으로 설치) |
| CUDA out of memory | 다른 GPU 프로그램을 끄거나 `--load-4bit` 사용 |
| 시작 전 점검에서 정상 단어를 못 읽음 | 그대로 두고 summary.md를 보내 주세요. 지시문이나 입력 형식을 고쳐야 할 수 있습니다. |

## 그 밖의 옵션

- `--model <이름>`: 다른 모델로 실행. Hugging Face의 표준 방식(AutoModelForImageTextToText와 채팅 템플릿)을 지원하는 모델이어야 합니다.
- `--sizes 12,16,32`, `--fonts gothic`, `--prompts neutral`, `--no-choice`: 조건 줄이기와 늘리기.
- `--save-images`: 모든 자극 이미지를 결과 폴더에 저장(논문 그림용).
- `--report-only`: 저장된 결과로 요약표만 다시 만들기.
